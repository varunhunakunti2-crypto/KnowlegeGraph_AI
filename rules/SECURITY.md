# SECURITY — Mandatory Security Rules

## File Security
1. Validate uploaded PDF signatures, MIME types, sizes, and page counts.
2. Generate server-controlled filenames.
3. Prevent path traversal and unauthorized file access.
4. Handle corrupted, encrypted, and empty documents safely.

## Database Security
5. Use parameterized SQL and Cypher queries.
6. Validate model-generated entities, relationships, and structured output.
7. Restrict graph labels and relationship types to approved schemas.
8. Never expose database ports publicly by default.

## AI Security
9. Treat PDF contents and retrieved passages as untrusted data.
10. Defend against prompt injection in documents.
11. Never allow document text to override system instructions.
12. Validate citations against retrieved source evidence.
13. Never execute code, SQL, or Cypher generated by the LLM.
14. Return an insufficient-evidence response when sources do not support an answer.

## Application Security
15. Store secrets in environment variables and exclude .env from Git.
16. Never expose credentials, tokens, internal paths, or raw stack traces.
17. Restrict CORS to configured frontend origins.
18. Enforce document and workspace access checks across all APIs and retrieval paths.
19. Apply upload limits, timeouts, and bounded concurrency.
20. Keep deletion consistent across files, embeddings, chunks, and graph evidence.
21. Do not log secrets or unnecessary document contents.

## Verification
Add regression tests for security fixes. Report unresolved vulnerabilities and unverified controls honestly.
